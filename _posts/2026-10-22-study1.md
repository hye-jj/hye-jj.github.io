## 1. 컴퓨터의 기본 구조

컴퓨터란 입력받은 데이터를 프로그램에 따라 처리하고, 결과를 출력하거나 저장하는 전자적 정보처리 장치입니다.

컴퓨터는 **하드웨어**와 **소프트웨어**로 구성됩니다.

- **하드웨어**: 눈에 보이는 물리적 장치 (CPU, 메모리, 저장장치, 입출력장치 등)
- **소프트웨어**: 하드웨어를 동작시키는 프로그램 (시스템 소프트웨어, 응용 소프트웨어)

컴퓨터의 기본 동작은 **입력 → 처리 → 출력**의 흐름이며, 처리 결과를 **저장**하는 과정이 함께 이루어집니다.

<br>

## 2. 컴퓨터의 5대 장치

| 장치 | 역할 | 예시 |
|---|---|---|
| **입력장치** | 외부 데이터를 컴퓨터 내부로 전달 | 키보드, 마우스, 스캐너 |
| **출력장치** | 처리 결과를 사용자에게 전달 | 모니터, 프린터, 스피커 |
| **기억장치** | 데이터와 명령어를 저장 | 주기억장치(RAM, ROM), 보조기억장치(HDD, SSD) |
| **연산장치** | 산술·논리 연산 수행 | ALU |
| **제어장치** | 명령어 해석 및 각 장치 동작 제어 | 제어 유닛(CU) |

> 연산장치 + 제어장치 = **CPU(중앙처리장치)**
> 중앙처리장치(CPU)는 일반적으로 연산장치, 제어장치, 레지스터 등으로 구성됩니다. 5대 장치 중 연산장치와 제어장치가 CPU의 핵심 기능에 해당합니다.


### 2-1. 연산장치 (ALU)
- 산술 연산(덧셈, 뺄셈 등)과 논리 연산(AND, OR, NOT 등) 수행
- 구성: 가산기, 보수기, 누산기, 데이터 레지스터, 상태 레지스터 등

### 2-2. 제어장치 (CU)
- 명령어를 해독하고 필요한 제어 신호를 발생
- 구성: 명령 레지스터(IR), 명령 해독기(Decoder), 프로그램 카운터(PC), 메모리 주소 레지스터(MAR), 메모리 버퍼 레지스터(MBR) 등

### 2-3. 기억장치
- **주기억장치**: CPU가 직접 접근, 속도가 빠르고 용량이 작음
  - RAM(휘발성, 읽기/쓰기), ROM(비휘발성, 주로 읽기)
- **보조기억장치**: 대용량·영구 저장, 속도가 상대적으로 느림
- **기억장치 계층 구조**: 레지스터 → 캐시 → 주기억장치 → 보조기억장치 (위로 갈수록 빠르고 비싸며 용량이 작음)

## 3. 폰 노이만(Von Neumann) 구조
![폰노이만 구조비교](https://velog.velcdn.com/images/superkkj/post/19533c11-5eba-4443-ace7-2eb8b308bc95/image.png)
- 출처 : https://velog.io/@superkkj/Velog-%ED%8F%AC%EC%8A%A4%ED%8C%85-%EC%B4%88%EC%95%88-CS-Deep-Dive-1%ED%8E%B8

### 3-1. 개념
**프로그램 내장 방식(Stored Program)**: 프로그램(명령어)과 데이터를 **같은 메모리**에 저장하고, CPU가 메모리에서 순차적으로 꺼내 실행하는 프로그램 내장 방식 구조입니다. 현대 컴퓨터 대부분이 이 구조를 기반으로 합니다.

### 3-2. 특징
- 명령어와 데이터가 하나의 메모리에 함께 저장
- CPU가 명령어를 인출(Fetch)하고 해독(Decode)하여 실행(Execute)
- 명령어를 **순차적으로** 실행 (순차 처리)
- 하나의 버스로 명령어와 데이터를 모두 전달
- 명령어와 데이터가 메모리와 CPU 사이의 통신 자원을 공유하여 병목현상이 발생할 수 있음

### 3-3. 장점과 단점
- **장점**: 구조가 단순하고 하드웨어 구현이 쉬우며, 프로그램 변경이 유연
- **단점**: **폰 노이만 병목현상(Von Neumann Bottleneck)** 발생
  - CPU와 메모리 사이의 버스를 명령어와 데이터가 공유하므로, 처리 속도가 버스 전송 속도에 제한됨
  - 해결 방안: 캐시 메모리, 파이프라이닝, 멀티코어 등

### 3-4. 하버드 구조와의 비교
비교 개념: 하버드 구조는 명령어와 데이터의 기억 공간 및 접근 경로를 분리합니다.
| 구분 | 폰 노이만 구조 | 하버드 구조 |
|---|---|---|
| 메모리 | 명령어·데이터 **통합** | 명령어·데이터 **분리** |
| 버스 | 단일 버스 | 별도 버스 |
| 병목현상 | 발생 | 완화 |
| 구조 | 단순 | 복잡 |
| 활용 | 범용 컴퓨터(PC 등) | 임베디드, DSP |

<br>

> 💡 현대의 CPU는 "외부(RAM)는 폰 노이만, 내부(L1)는 하버드"를 사용하는 하이브리드(Modified Harvard) 구조

<br>

## 4. 명령어 실행 사이클 (참고)

1. **인출(Fetch)**: PC가 가리키는 주소의 명령어를 메모리에서 가져옴
2. **해독(Decode)**: 명령어를 해독
3. **실행(Execute)**: ALU 등이 연산 수행
4. **저장(Write Back)**: 결과를 레지스터나 메모리에 저장


<br>

## 5. 핵심 포인트

- 5대 장치: **입력, 출력, 기억, 연산, 제어** (연산 + 제어 = CPU)
- 폰 노이만 구조의 핵심은 **프로그램 내장 방식**
- 폰 노이만 병목현상의 원인은 **명령어와 데이터가 같은 버스를 공유**하기 때문
- 하버드 구조는 **명령어/데이터 메모리 분리**로 병목현상을 완화
- 제어장치 관련 레지스터(PC, IR, MAR, MBR)의 역할을 구분해서 암기
