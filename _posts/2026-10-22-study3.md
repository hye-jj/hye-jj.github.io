CPU는 컴퓨터의 두뇌로, 컴퓨터일반에서 **레지스터의 역할 구분**과 **명령어 사이클(마이크로 연산)**이 중요합니다.

## 1. CPU(중앙처리장치)의 구성
- ALU, 제어장치, 레지스터, PC, IR

CPU는 크게 **연산장치(ALU)**, **제어장치(CU)**, **레지스터**로 구성되며, 이들은 내부 버스로 연결됩니다.

| 구성 요소 | 역할 |
|---|---|
| **ALU** | 산술·논리 연산 수행 |
| **제어장치(CU)** | 명령어를 해독하고 각 장치에 제어 신호 전달 |
| **레지스터** | CPU 내부의 **가장 빠른 임시 저장장치** |
| **Clock** | CPU 동작의 기준 타이밍 제공 |

### 시스템 버스

| 버스 | 방향 | 역할 |
|---|---|---|
| **주소 버스** | 단방향 (CPU → 메모리/입출력) | 접근할 위치의 주소 전달 |
| **데이터 버스** | 양방향 | 데이터 전달 |
| **제어 버스** | 양방향 | 읽기/쓰기, 인터럽트 등 제어 신호 전달 |

> 주소 버스의 폭이 **접근 가능한 메모리 크기**를, 데이터 버스의 폭이 **한 번에 전송하는 데이터 양**을 결정합니다. (주소 버스 n비트 → 2ⁿ개의 주소)

<br>

## 2. 레지스터의 종류

### 2-1. 핵심 레지스터 (필수 암기)

| 레지스터 | 명칭 | 역할 |
|---|---|---|
| **PC** | 프로그램 카운터 | **다음에 실행할 명령어의 주소**를 저장 |
| **IR** | 명령어 레지스터 | **현재 실행 중인 명령어**를 저장 |
| **MAR** | 메모리 주소 레지스터 | 메모리에 접근할 **주소**를 저장 |
| **MBR (MDR)** | 메모리 버퍼 레지스터 | 메모리에서 **읽어온/쓸 데이터**를 저장 |
| **AC(Accumulator)** | 누산기 | **연산 결과를 임시 저장** |
| SP (Stack Pointer) |  | 스택의 최상단 위치 관리 |
| 상태 레지스터 |  | Zero, Carry, Overflow 등의 상태 플래그 저장 |

> 자주 헷갈리는 개념: PC는 명령어의 주소, IR은 명령어 자체를 저장합니다.

### 2-2. 기타 레지스터

| 레지스터 | 역할 |
|---|---|
| **SP (스택 포인터)** | 스택의 **최상위(Top) 주소**를 가리킴 |
| **상태 레지스터 (PSW/FLAG)** | 연산 결과의 상태와 CPU 상태를 저장 |
| **인덱스 레지스터** | 주소 계산 시 **인덱스 값**을 저장 (배열 접근 등) |
| **베이스 레지스터** | 기준 주소를 저장 |
| **범용 레지스터** | 용도 제한 없이 데이터·주소를 임시 저장 |

### 2-3. 상태 레지스터의 플래그

- **캐리(C)**: 자리올림 발생
- **부호(S)**: 연산 결과의 부호
- **영(Z)**: 연산 결과가 0
- **오버플로우(V)**: 표현 범위 초과
- **인터럽트 가능(I)**: 인터럽트 허용 여부
- **패리티(P)** 등

### 2-4. 헷갈리기 쉬운 포인트
- **PC는 주소**를 저장하고, **IR은 명령어 자체**를 저장합니다.
- **MAR는 주소**, **MBR는 데이터**를 저장합니다.
- 분기(점프) 명령이 실행되면 PC 값이 **분기 목적지 주소**로 바뀝니다. 그렇지 않으면 PC는 순차적으로 증가합니다.

## 3. 명령어의 구성

명령어는 **연산자(OP code)** 와 **오퍼랜드(Operand)** 로 이루어집니다.

<img src="https://velog.velcdn.com/images/hajju/post/be169d78-9326-4ed4-a31a-c21e09717556/image.png" width="520" height="180"/> <br>

- 연산코드(operation code) 필드 : **수행할 연산** 처리해야 할 연산의 종류를 나타냄. 수행할 연산을 위한 명령어를 나타내는 필드.
- 오퍼랜드(operand) 필드 : **피연산자 및 주소정보** 처리할 정보나 처리된 정보를 나타냄. 즉, 피연산자를 의미. 연산코드에서 결정된 명령을 수행할 대상이 되는 데이터 or 데이터가 저장된 주소를 나타내는 필드.

<br>

| 연산자(OP code) 기능 | 예시 |
|---|---|
| 함수 연산 | 산술, 논리, 시프트 |
| 전달 | LOAD, STORE, MOVE |
| 제어 | 분기(JUMP), 서브루틴 호출 |
| 입출력 | READ, WRITE |

### 명령어 형식 (주소 필드 수 기준)

| 형식 | 특징 |
|---|---|
| **0-주소** | 오퍼랜드 없음, **스택**을 사용 (PUSH, POP) |
| **1-주소** | 오퍼랜드 1개, **누산기(AC)** 를 묵시적으로 사용 |
| **2-주소** | 오퍼랜드 2개, 연산 결과를 한쪽에 덮어씀 (가장 일반적) |
| **3-주소** | 오퍼랜드 3개, 원본 보존 가능, 프로그램은 짧지만 **명령어 길이가 김** |

<br>

## 4. 명령어 사이클 (Instruction Cycle)

CPU가 명령어 하나를 처리하는 전체 과정입니다. 기본 흐름은 **인출 → (간접) → 실행 → (인터럽트)** 입니다.

### 4-1. 인출 사이클 (Fetch Cycle)
메모리에서 명령어를 가져오는 단계로, **모든 명령어에 공통**입니다.

```
t0: MAR ← PC               (PC의 주소를 MAR로)
t1: MBR ← M[MAR], PC ← PC + 1   (메모리에서 명령어를 읽고 PC 증가)
t2: IR ← MBR               (명령어를 IR로 이동, 이후 해독)
```

### 4-2. 간접 사이클 (Indirect Cycle)
**간접 주소 지정**일 때만 수행합니다. 오퍼랜드가 가리키는 곳에 **유효 주소**가 들어 있으므로 메모리를 한 번 더 읽습니다.

```
t0: MAR ← IR(addr)
t1: MBR ← M[MAR]
t2: IR(addr) ← MBR(addr)
```

### 4-3. 실행 사이클 (Execute Cycle)
해독된 명령어를 실제로 수행하며, **명령어마다 마이크로 연산이 다릅니다.**

> 예) ADD 명령 (AC ← AC + M[addr])
> ```
> t0: MAR ← IR(addr)
> t1: MBR ← M[MAR]
> t2: AC ← AC + MBR
> ```

### 4-4. 인터럽트 사이클 (Interrupt Cycle)
인터럽트가 발생하면 현재 실행 상태를 저장하고 **인터럽트 서비스 루틴**으로 분기합니다.

```
t0: MBR ← PC                       (복귀 주소 보존)
t1: MAR ← SP(저장 위치), PC ← 인터럽트 루틴 시작 주소
t2: M[MAR] ← MBR                   (복귀 주소를 저장)
```

처리가 끝나면 저장해 둔 PC 값을 복원해 **원래 프로그램으로 복귀**합니다.

### 4-5. 사이클 흐름 정리

| 사이클 | 수행 조건 | 핵심 동작 |
|---|---|---|
| 인출 | 항상 | 명령어를 가져와 IR에 저장, PC 증가 |
| 간접 | 간접 주소 지정 시 | 유효 주소를 얻기 위해 메모리 재접근 |
| 실행 | 항상 | 명령어 해독 후 연산 수행 |
| 인터럽트 | 인터럽트 발생 시 | PC 등 상태 저장 후 서비스 루틴으로 분기 |

<br>

## 5. 주소 지정 방식 (Addressing Mode)

| 방식 | 특징 | 메모리 접근 |
|---|---|---|
| **즉시(Immediate)** | 오퍼랜드가 **데이터 자체** | 0회 |
| **직접(Direct)** | 오퍼랜드가 **유효 주소** | 1회 |
| **간접(Indirect)** | 오퍼랜드가 **유효 주소가 저장된 주소** | 2회 이상 |
| **레지스터(Register)** | 데이터가 레지스터에 있음 | 0회 |
| **레지스터 간접** | 레지스터에 유효 주소가 있음 | 1회 |
| **변위(Displacement)** | 레지스터 값 + 오퍼랜드로 유효 주소 계산 | 1회 |

변위 주소 지정은 기준 레지스터에 따라 나뉩니다.
- **상대(Relative)**: PC + 변위 / PC와 변위 값을 이용해 주소 계산
- **인덱스(Index)**: 인덱스 레지스터 + 변위 (배열 접근) / 인덱스 레지스터와 주소 필드를 이용해 유효주소 계산
- **베이스 레지스터(Base)**: 베이스 레지스터 + 변위 (재배치에 유리)

## 6. 제어장치의 구현 방식

| 구분 | 하드와이어드 방식 | 마이크로프로그램 방식 |
|---|---|---|
| 방법 | 논리회로로 직접 구현 | 제어 신호를 **제어 메모리**에 저장 |
| 속도 | **빠름** | 상대적으로 느림 |
| 유연성 | 변경이 어려움 | **변경·확장이 쉬움** |
| 주 사용 | RISC | CISC |

<br>

## 7. CISC와 RISC

| 구분 | CISC | RISC |
|---|---|---|
| 명령어 | 많고 복잡, **가변 길이** | 적고 단순, **고정 길이** |
| 레지스터 | 적음 | **많음** |
| 메모리 접근 | 여러 명령어가 접근 가능 | **LOAD/STORE만** 접근 |
| 제어 방식 | 마이크로프로그램 | 하드와이어드 |
| 파이프라인 | 효율이 낮음 | **효율이 높음** |

<br>

## 8. 핵심 정리

1. CPU = **ALU + 제어장치 + 레지스터**
2. **PC는 다음 명령어 주소**, IR은 현재 명령어, MAR는 주소, MBR는 데이터, AC는 연산 결과
3. 인출 사이클의 순서는 **MAR ← PC → MBR ← M[MAR], PC ← PC+1 → IR ← MBR**
4. **간접 사이클**은 간접 주소 지정일 때만, **인터럽트 사이클**은 인터럽트 발생 시에만 수행
5. 명령어 형식은 **0주소(스택), 1주소(AC), 2주소(일반), 3주소(원본 보존)**
6. 주소 지정에서 **즉시는 메모리 접근 0회**, 직접은 1회, 간접은 2회 이상
7. 하드와이어드는 **빠르고 변경이 어렵고**, 마이크로프로그램은 **느리지만 유연**
